This documents the difference between Chrome's [[[usermedia-mvp]]] and [[mediacapture-extensions]]'s [[[mediacapture-extensions#media-capture-html-elements]]].

This is a purely informational note about a particular implementation and how it relates to its relevant specification.

Introduction

Chrome introduced the usermedia element as en experimental [[origin-trials|Origin Trial]] in Chrome M144. Later standardization in [[mediacapture-extensions]] modified the API and behavior of usermedia. Chrome will adapt its implementation to follow [[mediacapture-extensions]]. Web page authors should adapt their usage accordingly. A migration guide can be found in [[usermedia-migration-guide]].

This note documents the differences between usermedia elements as shipped by Chrome in origin trials and intermediate versions and the final API specified in [[[mediacapture-extensions#media-capture-html-elements]]]. This is note is only informational.

Differences between Chrome's [[[usermedia-mvp]]] and [[[mediacapture-extensions#media-capture-html-elements]]]

The usermedia element support in Chrome is developed in several phases.

The initial public release ("MVP") will support the API specified in [[[mediacapture-extensions#media-capture-html-elements]]]. The older API shape ([[[#original-pepc]]]) will be supported behind an origin trial ([[[usermedia-legacy-origin-trial]]]), to allow origin trial participants to transition on their own timeline. The current plan is to end the [[[usermedia-legacy-origin-trial]]] on November 3rd, 2026.

soon — Post-MVP
We expect future developments of the API to be first specified in [[mediacapture-extensions]].
M153 & later — <usermedia>, <camera>, and <microphone> elements.
The first publicly available version implements [[[mediacapture-extensions#the-usermedia-html-element]]]. Behaviours not covered by the current version of the spec, like what happens when the element is activated while a stream is playing ("second click"), are postponed to any post-MVP versions.
M144 - M152 — <usermedia> element [[[origin-trials|origin trial]]]
The original implementation, based on the original [[[pepc#page-embedded-permission-control-pepc]]] design, described in [[[#original-pepc]]]. This API was available originally behind an origin trial. For a limited time it will continue to be available behind the [[[usermedia-legacy-origin-trial]]] origin trial, concurrently with the MVP, as an [[[origin-trials#deprecation_trials|reverse origin trial]]].
pre M144 — <permission> element [[[origin-trials|origin trial]]]
[[[pepc]]]'s permission element is the ancestor of usermedia. It is no longer supported.

First public version / MVP, M153

The [[usermedia-mvp|MVP]]'s usermedia element uses the following [=element interface=]. camera and microphone element are analogous. These elements and their interfaces are fully specified in [[[mediacapture-extensions#the-usermedia-html-element]]]. 

    [Exposed=Window]
    interface HTMLUserMediaElement : HTMLElement {
      [HTMLConstructor] constructor();

      readonly attribute MediaStream? stream;
      readonly attribute DOMException? error;
      undefined setConstraints(optional HTMLMediaStreamConstraints constraints = {});

      attribute EventHandler onstream;
      attribute EventHandler oncancel;
      attribute EventHandler onerror;
    };

The main differences to the legacy API are:

  • Eliminate the type and isTypeSupported attributes, and instead have three different element types.
  • The stream is now directly accessible as an attribute.
  • The "blocker" logic still exists, but is not exposed to the developer.

Legacy PEPC API

This is the original implemenation of usermedia, behind the Trial for UserMediaElement [[origin-trials|origin trial]]. This trial will temporarily in place, as a [[[origin-trials#deprecation_trials|reverse origin trial]]], to give the original users more time for a smooth transition.

The legacy API is largely that described by [[[usermedia-legacy]]]. The differences to the [[mediacapture-extensions]] version are as follows: 

      [Exposed=Window]
      interface HTMLUserMediaElement : HTMLElement {
        [HTMLConstructor] constructor();

        undefined setConstraints(MediaStreamConstraints constraints);
        readonly attribute DOMException? error;

        [Reflect] attribute DOMString type;
        boolean isTypeSupported(DOMString type);
      };
      HTMLUserMediaElement includes ActivationBlockersMixin;
      HTMLUserMediaElement includes PowerfulFeatureObserver;

The stream attribute, error attribute, and setConstraints() method work as in [[mediacapture-extensions]]'s usermedia element.

The type IDL attribute reflects the `type` content attribute. Depending on {{HTMLUserMediaElement/type}}, the usermedia element changes behaviour:

`"microphone camera"`
`"camera microphone"`
— behaves like a regular usermedia element.
`"microphone"`
— behaves like a microphone element.
`"camera"`
— behaves like a camera element.
all other values
— behaves like an {{HTMLUnknownElement}}.

The isTypeSupported() method can be used to query whether a given type is supported by this element. It will return true if the input string is one of `"microphone camera"`, `"camera microphone"`, `"microphone"`, or `"camera"`, and false in all other cases.

The {{ActivationBlockersMixin}} formalizes several "click-jacking" protections, and exposes their state in {{ActivationBlockersMixin/isValid}}, {{ActivationBlockersMixin/invalidReason}}, and {{ActivationBlockersMixin/onvalidationstatuschange}} attributes. [[mediacapture-extensions]] [[[mediacapture-extensions#dfn-trusted|encourages]]] similar "click-jacking" protections, it does specify them in details, and does not expose their inner state to developers or users.

The {{PowerfulFeatureObserver}} formalizes access into the [[permissions]] API using the "camera microphone" permission descriptor (or the suitable substrings, as appropriate). [[mediacapture-extensions]] eschews direct calls to [[permissions]] APIs and instead relies on {{MediaDevices/getUserMedia()}} to handle permission requests internally, and consequently relies on [[mediacapture-streams]] to describe the suitable interactions with [[permissions]].
